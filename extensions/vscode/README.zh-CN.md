# Harmony Agent for VS Code

[English](README.md)

在 VS Code 里直接操作鸿蒙手机，查看当前页面的控件，或回放保存在电脑上的流程。需要重复一段操作时，再开始录制。

## 安装

使用桌面版 VS Code 1.101 或更新版本，并打开受信任的工作区。连接手机时，在同一台电脑上运行 VS Code、Python 3.10+ 和官方 HDC。扩展版本为 `0.20.33`。混合坐标手势与控件步骤需要运行时 `0.1.0a11` 或更新版本，交互式流程调试至少需要 `0.1.0a10`。

从源码安装时，克隆[项目仓库](https://github.com/andyandymike/harmony-automation-agent)，安装 Node.js 22+，在 Windows 上从仓库根目录运行以下命令。

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install .
Set-Location extensions/vscode
npm run package
code --install-extension ./harmony-agent-workbench-0.20.33.vsix
```

macOS 和 Linux 上使用 `.venv/bin/python`，并用 `cd extensions/vscode` 进入扩展目录。已有 wheel 和 VSIX 时，在选定的 Python 环境运行 `python -m pip install --no-index --no-deps ./harmony_automation_agent-0.1.0a11-py3-none-any.whl`，再通过 **扩展 → 从 VSIX 安装…** 装入 VSIX。开发或打包扩展时才需要 Node.js。

在 VS Code 用户设置中，将 `harmonyAgent.cliPath` 设为仓库虚拟环境中 CLI 的绝对路径。Windows 用 `.venv/Scripts/harmony-agent.exe`，macOS 和 Linux 用 `.venv/bin/harmony-agent`。HDC 不在 PATH 中时填写 `harmonyAgent.hdcPath`。工作台默认跟随 VS Code 的显示语言，也可以将 `harmonyAgent.language` 设为 `en` 或 `zh-CN`。

### 项目运行时

本地项目可在工作区根目录放置 `.harmony-agent/runtime.json`，由初始化脚本填写本机路径。相对路径以包含 `.harmony-agent` 的工作区文件夹为基准。`cli` 是可用 `python <cli>` 启动的 Python 入口脚本。

```json
{
  "version": 1,
  "python": ".venv/Scripts/python.exe",
  "cli": ".harmony-agent/launch.py",
  "src": "src",
  "hdc": "tools/hdc.exe"
}
```

入口脚本可导入并调用 `harmony_agent.cli` 的 `main()`。macOS 或 Linux 上可改用 `.venv/bin/python` 和本机 HDC 的路径。`src` 放在子进程 `PYTHONPATH` 的最前面。

在受信任的工作区打开工作台并确认使用。多根工作区中有多个候选时，先选择项目。选择仅保存在当前工作区。可在工作台设置菜单或命令面板运行 **Harmony Agent: 选择项目运行时** 更换项目。没有配置文件时沿用 VS Code 设置和 PATH 发现。已选文件失效或被删除时，工作台会显示原因。可通过同一命令主动切回 VS Code 设置。

CLI、Copilot MCP、流程调试、手机预览、网络工具、pytest 和复制到 Codex 的 MCP 配置共用这套运行时。配置重新保存后会校验，进行中的运行或采集结束后生效。HDC 路径改变后，可刷新设备。已粘贴到 Codex 的 MCP 配置可重新复制以获取改动。

## 打开工作台

点击最左边活动栏的 **Harmony Agent** 图标，编辑区会打开工作台，左侧显示项目树。要保留搜索等其他侧栏，可用左下角状态栏的 **Harmony Agent**，或在命令面板运行 **Harmony Agent: 打开工作台**。资源管理器标题栏的手机图标也可以打开工作台。切换右侧的 **测试**、**元素**、**网络调试** 和 **AI 探索** 时，左侧保留手机画面。查看已保存的流程和导入 HAR 都可以离线进行。需要操作手机时，用 USB 数据线连接手机并允许 HDC 调试。工作台会自动选中唯一连接的手机。连接多台时，在顶部选择要用的手机。

| 我现在想做什么 | 在工作台怎么做 |
|---|---|
| 手动操作手机 | 在左侧画面单击、双击、长按或滑动，按住再移动可以拖拽。滚轮可滑动，**Ctrl + 滚轮** 或触屏双指可缩放。画面上方可使用 **手机返回**、**主页**、**最近任务** 和 **键盘**。 |
| 找到一个按钮并操作它 | 打开 **元素**。可以直接点左侧画面中的控件，也可以按文字或 ID 搜索。选中后即可查看定位信息、点按，或对适用控件输入文字和滚动。 |
| 回放已有流程 | 在 **测试** 打开本地流程文件，核对步骤。把手机放回起始页面，再点 **在手机上回放**。 |
| 查看上次执行到哪一步 | 选用例，点「查看报告」和对应步骤的状态。断开手机也能查阅已保存的结果。 |

完成回放后，带结果检查的流程会显示检查结果。按坐标录制的流程会显示各步的设备回执。没有最终检查时，「已完成」表示设备执行了步骤。

## 选取元素、调试流程与查看网络

在 **元素** 页用左侧画面上方的 **选取元素** 切到快照。点击控件后，右侧显示它的父节点、属性和可编辑的定位器。刷新控件可以复验定位，也可以固定观察属性或把点按和断言加入流程草稿。切回 **实时操作** 即可在左侧操作手机。元素列表可多选并复制筛选结果中的定位器。固定观察和流程草稿中的步骤也可批量移除。

在元素页，右上角的 **设置** 菜单提供 **打开应用** 和 **屏幕截图**。点手机画面上方的 **断开**，工作台会释放设备会话并清空当前画面和控件树。点同一个位置的 **重新连接**，即可按当前模式恢复实时画面或刷新元素快照。

打开按控件执行的流程，展开 **运行配置与调试 → 断点与单步调试**。暂停时可验证定位器、单步执行、继续或停止。运行器会保留变量、条件分支和循环进度。步骤里的 **导出运行证据** 和探索报告里的 **导出探索证据** 可保存离线 HTML。在 VS Code 命令面板执行 **Harmony Agent: 打开已导出的证据** 即可查看。

打开 **网络调试**。在「网络请求」里采集调试应用的原生 HTTP，也可连接 ArkWeb 或导入 HAR。用方法、域名和状态码筛选请求，在保留的头和正文中查找故障线索。选中请求可对比记录，或编辑后发往本地测试网关一次。在「模拟与改写」中，用规则组管理改写规则和顺序响应，先在历史请求上预览，再查看新请求的实际命中。 [网络调试使用说明](NETWORK.md)

## 探索测试

打开 **AI 探索** 标签，或从命令面板运行 **Harmony Agent: 探索测试**。在手机上打开目标应用，选择一种方式。

- **探索当前页面**。可写下重点，例如“优先查看设置和帮助”。助手从当前可识别的控件选取入口，工作台记录实际到过的页面、操作与返回路径。默认预算是 20 次设备输入或 3 分钟，可在开始前调整。
- **探索用例的其他走法**。在「AI 探索」里选一个用例，再选 **用例起点** 或某一步之后，也可以从「测试」里右键步骤进入。可以先离线选择用例和位置。开始后，脚本执行到该位置，AI 才读取到达画面的控件，最多尝试两条其他走法。列表会标出脚本可到达的位置，并说明其余位置的限制。

随时可暂停并接手手机。继续时要选中原设备，恢复之前的页面状态。关闭工作台会暂停当前探索。在 **AI 探索 → 探索记录** 可离线查看历史。在 **测过的地方** 展开页面查看哪些入口试过，哪些跳过。**发现** 区分已采用的断言失败、尚待复核的观察和测试受阻。打开 **操作记录** 可查看已有的前后冻结控件。对于带稳定定位和明确预期的失败，可以选择 **保存为回归流程**，再从相同起点回放。探索记录和运行证据保存在本机，模型会收到当前任务所需的控件及候选操作。

用例探索报告会显示前置脚本是否到达分叉位置，以及每条实际尝试的走法。点某条走法的 **预览为新用例**，可以核对保留的前置步骤和此次走出的分支，再单独命名、保存。新用例只包含这条路径实际执行的内容。待复核项可以添加备注，也可以多选后一起忽略或重新打开。对支持独立复测的断言失败，把原设备放回起始页，点 **独立复测** 查看复现结果。

## 手动录制

在手机画面上方点 **开始录制**，然后直接触屏或点击预览。第一次操作决定本次录制的位置，直到结束录制。真机触屏采集不可用时，可以在预览画面录制。录制步骤会显示在 **测试** 中。

能唯一定位控件的点击按控件保存，其余受支持的手势按屏幕位置保存。UiTest 从 API 20 起可提供触屏时的控件信息。混合两类步骤的流程需要运行时 `0.1.0a11` 或更新版本。

发送文字时，先点手机画面里的输入框，再打开 **键盘** 输入或粘贴文字并发送。**最近任务**使用手机的手势导航。缩放需要手机支持注入双指触控。

点 **结束录制** 后核对步骤。坐标录制中暂不支持的手势可在审阅时移除，回放时需要相同的屏幕尺寸、方向和布局。点 **保存录制** 写入 JSON，或点 **保存为测试用例** 按执行顺序核对 BDD 步骤。

## 在插件里管理测试用例

打开 **测试** 可以看到录制和 AI 探索保存的用例。点 **打开文件** 可打开已有用例或流程 JSON。点已保存用例的名称或可编辑的 `Given / When / Then` 行即可修改。匹配当前流程的运行状态会显示在步骤旁，点状态可查看证据。「用例历史」可查看以前的报告。

录制结束后选择 **保存为测试用例**。AI 探索结束后，从报告选择一条可重放路径或具体发现，再核对步骤。可在保存前补充起始条件和最终预期。尚无业务断言的流程可先存下来回放；坐标手势按原设备布局回放。将新的用例目录一起提交到项目，即可保留步骤和用例来源。

点 **新建用例** 可以从空步骤列表开始。在需要的位置点 **插入步骤 → 插入验证**，开头、中间和末尾使用同一张表单。**用 AI 整理步骤** 会根据用例目标、已有检查和录下的页面线索，为步骤建议名称、分组和 BDD 角色，核对后再保存。

在支持批量操作的列表里，点 **多选** 或用鼠标左键长按一行。勾选哪一项，就显示哪一项的详情。取消当前项，会回到上一条仍勾选的内容。也可以按住 Ctrl 单击逐项勾选（macOS 用 Cmd），按住 Shift 单击选择一段。**全选** 覆盖当前列表或筛选结果，**取消全选** 会清空勾选并保留多选模式。切换页签、变更筛选条件或开始其他操作时，会退出多选。

在多选工具栏或勾选步骤的右键菜单中，可以 **保存片段**、**用所选步骤新建用例** 或 **删除所选**。片段会按原有顺序保存同一组流程中勾选的步骤。全选用例时，片段也会带上起始条件和最终断言。**删除所选** 会将改动留在用例草稿，点 **撤销删除** 可以恢复整批。

双击步骤或右键选 **编辑步骤**，可以直接修改名称、BDD 角色、描述和分组。需要调整操作或断言时，展开 **执行设置**。选择定位器时，打开控件所在页面，点 **在画面中选取**。在左侧单击选取控件，重叠时可右键选择。**读取当前页控件** 提供可搜索的列表。核对这一步后点 **应用到草稿**，全部编辑完成后点 **保存用例修改**。在步骤行右键或点 **⋯**，菜单标题会指明当前步骤，可从中编辑、复制或保存片段。在两步之间或列表末尾右键，可以在该位置补充当前用例，也可以从这里新建用例。直接点击分隔线可打开插入选项。

用例库可多选后批量移除，移除整批可一次撤销，项目文件会保留。录制审阅列表也可多选、删除和撤销。断点列表支持全选及取消全选。

新用例与磁盘上的目录同名时，插件会加数字后缀另建目录。

在标题旁选择 **工作台** 或 **pytest**，再点 **运行**。在失败报告里展开 **原失败证据**，可以查看记录的画面和关联请求。点 **用 AI 分析失败** 可获取定位器、等待或页面跳转建议。定位失败而证据不足时，可以在手机上打开对应页面，再点 **用手机当前画面补充分析**。点 **试跑修复**，会从用例起点验证原失败步骤，进度和 **试跑详情** 都在原报告里。原失败步骤通过后，可以 **应用到用例**。要验证整条流程，可以点 **运行当前用例**。缺少测试上游时，可以在报告里填写地址试跑，确认请求已到达上游后点 **保存测试上游**。需要手动调整建议时，展开 **修复改动**，选择在用例编辑器中调整。

### 复用现有用例或用探索补充步骤

把指针移到两步之间，点击出现的定位线。也可以在右键菜单指定前后位置。开头、中间和结尾都可以 **写步骤描述** 或 **引用已有用例**。描述可以和录制步骤、引用混排并保存为草稿。点待生成行的 **生成步骤**，在 AI 探索回放前面的可执行步骤，或把手机停在此步的起始页。核对生成的动作和断言后应用到用例。列表保留你的原句，展开可看具体步骤。完成所有待生成项后即可正式运行，满足起止检查后可导出 pytest。

引用搜索支持用例名、步骤和标签，选中后可展开 **预览步骤**。复用连续步骤时，在其中任意一步的菜单里选 **保存可复用片段**，选择 **起始步骤** 和 **结束步骤**，核对选中的步骤后保存。坐标录制加入控件动作或检查后，仍保留原坐标和手势间隔，并在同一个设备会话中运行。

需要 AI 修改已有步骤时，在该行右键选 **用 AI 修改此步**。填写修改意见后，在原位置核对生成的动作和断言，再应用到用例。

跨步骤的更改可以写在 **用例修改意见**。把单步意见和插入描述加入草稿后，点 **探索整个草稿**。探索会在同一个设备会话中按新顺序执行。核对修改后，将手机恢复到用例起始状态并点 **验证整条回放**，通过后可 **保存为可回放版本**。分支或循环内有待处理项时，先在那条步骤对应的手机页面生成步骤。

引用在插入点执行已保存的步骤。**引用管理** 可筛选待更新或来源不可用的条目，**查看引用位置** 可定位调用方。用例改名或移动后，引用跟随元数据中的身份。来源步骤有更新时，可以核对差异、运行副本并采用新版。来源不可用时，可以继续运行已保存的版本，也可查找原用例、替换引用或转成当前用例的步骤。

补充当前用例时，在插入位置选 **用 AI 补充当前用例**。输入想执行的操作或验证的结果，点 **回放并探索**。工作台先按脚本执行到选定位置，再从到达的画面完成目标。核对新步骤后插入草稿，原有后续步骤会接在新步骤后面。要验证后续能否接着运行，可以运行整条用例。

如果要另写一个用例，选 **从此处新建用例 → 复制到这里的步骤**。新草稿可以单独命名、修改已有步骤、补充自己的操作和断言。只想复制其中几步时，勾选需要的顶层行，再点 **用所选步骤新建用例**。可以跳选，也可以勾选起始条件和最终断言，复制后仍按原顺序排列。条件、循环、描述或引用可整行勾选，内部步骤会一起带入。需要设备从该位置实际尝试其他入口时，选 **探索其他走法**。

建议把 `workflow.json` 和对应的 `.harmony-case.json` 元数据一起保存到项目。工作台可以回放坐标用例和运行控件用例。带 pytest 入口的控件用例也可通过独立 pytest 执行展开后的 `workflow.json`。需要保留引用布局时，请在工作台编辑组合用例。

## 将录制加入 pytest

按控件录制后，点 **保存为测试用例**，按执行顺序核对步骤。生成的 pytest 执行器要求有起始条件和最终断言。在已有控件流程的详情页也可选择 **生成 pytest 用例**。选择项目中的父目录并输入新用例名称，将可编辑的 `workflow.json` 与旁边的 `test_*.py` 一起提交。坐标手势可保存并在工作台回放。

在用例目录运行以下 PowerShell 命令。`--collect-only` 可以离线执行。实际运行需要该解释器已装 pytest、可用的 Harmony Agent CLI，以及已连接且处于预期起始页的指定设备。

```powershell
python -m pytest --collect-only -q .
$env:HARMONY_DEVICE = "你的设备 ID"
$env:HARMONY_ARTIFACT_DIR = "$PWD/artifacts"
python -m pytest -v . --junitxml=results.xml
```

在用例页点 **运行用例**，pytest 会使用选中的设备。启用项目运行时时，需要在项目指定的解释器中安装 `pytest`。使用 VS Code 设置时，默认使用 Python 扩展的活动解释器或 `python`，也可用 `HARMONY_PYTEST_PYTHON` 指定。`HARMONY_AGENT_CLI`、`HARMONY_HDC` 可指定工具路径。每次运行有独立的证据目录。CLI 状态默认保存在这个目录下，也可通过 `HARMONY_STATE_DIR` 指定位置。

运行结束后在插件内查看报告，或从运行记录重新打开。**查看测试阶段** 显示收集错误以及测试准备、执行、清理的结果和错误详情。步骤时间线显示实际执行的控件动作和断言，可以查看通过与失败时保存的页面。即使设备上的最终断言通过，pytest 清理失败仍会记录为用例失败。0.16.0 生成的用例可直接在此运行。

在 **测试** 中，在对应位置插入 **启用规则组** 和 **关闭规则组** 步骤。工作台回放到该步骤时会切换规则。启用步骤会把规则组快照保存到 `workflow.json`。如果 pytest 用例为整次运行配置了规则组，请设置项目的规则组 fixture。请设置 `HARMONY_RULE_GROUP_FIXTURE` 为项目**已注册**的 fixture 名称。它返回接收 `rule_group`、`device` 和 `state_dir` 三个关键字参数的函数，该函数返回上下文管理器，进入时准备规则和设备路由，退出时清理。以下示例中的 `project_gateway` 及其 `route` 方法由接入项目提供：

```python
# conftest.py
import pytest

@pytest.fixture
def harmony_route(project_gateway):
    def prepare(*, rule_group, device, state_dir):
        return project_gateway.route(device=device, rules=rule_group, state_dir=state_dir)
    return prepare
```

终端可用 `$env:HARMONY_RULE_GROUP_FIXTURE = "harmony_route"` 选择这个 fixture；工作台也可以在启动时输入名称。缺少 fixture 时，pytest 会在设备操作前报告失败。

## 离线与草稿

在 **测试** 打开本地流程或选中用例。离线时仍可核对步骤和已保存的证据。用例历史可查看同一个用例的多次结果，全部运行可查看跨用例的记录。连接对应手机后即可回放。

切换到其他编辑器会暂停预览采集，切回工作台时会恢复原先运行的预览。关闭工作台会结束正在进行的录制，取消当前 AI 请求，并停止正在进行的坐标回放。在同一 VS Code 窗口重新打开工作台，可以继续审阅录制草稿。要跨窗口重载或退出保留，请先点 **保存录制** 写入文件。

## 需要 AI 协助时

在 **AI 探索** 页展开 AI 助手，输入任务目标或让 AI 解读当前屏幕。执行过程中可以查看进度、停止任务。如果任务产生了可复用的控件步骤，可以在结果中审阅并保存。录制后的检查建议、运行结果里的步骤解释也由 AI 提供。手动操作、控件检查、录制和回放都可以在未配置模型时使用。

## AI 提供方设置

打开工作台的 **设置** 菜单，点 **AI 提供方设置**。探索测试、真机任务、录制检查建议和步骤解释都使用 `harmonyAgent.aiProvider` 选定的模型。

- **GitHub Copilot** 是 AI 命令的默认提供方。在 VS Code 登录 Copilot 账号。若 VS Code 询问模型使用权限，允许 Harmony Agent 使用模型。
- **Codex** 需要已登录的本机 Codex CLI 0.146.0 或更新版本。需要登录时运行 `codex login`，在设置中选 `codex`。如果找不到可执行文件，填写 `harmonyAgent.codexPath`。

使用这些 AI 功能时，所选提供方会收到任务目标以及相关页面控件或运行证据。

## 可选的外部聊天与 MCP

想在 Copilot Chat 或 Codex 桌面应用中继续对话时，在命令面板运行 **Harmony Agent: 在外部 AI 聊天中继续**，选择聊天工具，在聊天窗口核对草稿后发送。

- **Copilot Chat。** 在命令面板运行 **MCP: List Servers**，启动 **Harmony Agent**，在 Chat 的 Agent 模式启用其工具。项目仓库中的 `skills/harmony-agent` 可复制到被测项目的 `.github/skills/harmony-agent`，为聊天提供设备操作和流程验证说明。[VS Code MCP 说明](https://code.visualstudio.com/docs/copilot/customization/mcp-servers)
- **Codex 桌面应用。** 在外部聊天菜单点 **复制 Codex MCP 配置**，将生成的 `[mcp_servers.harmony]` 配置加入受信任项目的 `.codex/config.toml`，在该项目中新开对话。要把后续草稿发往同一项目，可设置 `harmonyAgent.codexProjectPath`。要跨窗口查看同一份运行记录，可将 `harmonyAgent.stateDir` 指向相同的证据目录。[Codex MCP](https://developers.openai.com/codex/mcp/)

## 开发

用桌面版 VS Code 打开 `extensions/vscode` 目录，按 F5 启动扩展开发宿主。**Harmony Agent: 打开工作台** 会使用用户设置或 PATH 指定的 CLI。在扩展目录使用 Node.js 22+ 运行 `npm test` 可执行离线测试。若要包含生成用例和报告的测试，请为测试用 Python 安装 `pytest`。解释器不在 PATH 中时可设置 `HARMONY_TEST_PYTHON`。
